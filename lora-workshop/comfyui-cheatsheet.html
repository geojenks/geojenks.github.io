1 · The three habits

Start from a graph that already runs. Never build from an empty canvas. Every workflow in comfyui/ has been run and ships with its result inside it.

Drag a PNG onto the canvas and the whole workflow comes back — every node, every value, every seed. That is how workflows are shared. It works on any image ComfyUI saved, including one you pull off the box next month.

Change one thing at a time. Same as reading training grids: fix everything, vary one value, look. A graph where you changed four things and it broke tells you nothing.

3 · Every model family wires up differently

This is the thing that catches everyone: you find a graph online, swap in the model you have, and it breaks. Not your fault — the left-hand end of the graph is family-specific.

LoadersSteering
SDXL / SD1.5CheckpointLoaderSimple — one file, everything insidecfg 7.0
Flux.1UNETLoader + DualCLIPLoader (clip_l and t5xxl) + VAELoadercfg 1.0 + FluxGuidance 3.5
Flux.2-kleinUNETLoader + CLIPLoader (qwen_3_4b, type flux2) + its own flux2-vaecfg 4.0

Flux uses guidance, not CFG. Leave cfg at 1.0 and set FluxGuidance instead — doing it the SDXL way gives you sludge. And Flux.1-Fill wants guidance around 30, not 3.5; it looks broken until you set it.

4 · Using your own LoRA

It's already in the dropdown — extra_model_paths.yaml points ComfyUI at the queue's output, so a run appears the moment it finishes.

  • Pick the .safetensors, not the optimizer.pt sitting next to it. That's training state, and choosing it gets you a stack trace.
  • Every 250-step checkpoint is listed separately. ..._000003000.safetensors is step 3000; the bare name is the final one — which is not necessarily the best one.
  • strength_model scales the whole correction. It does not separate subject from style; it moves the trade between them. Train past where you want to sit, then dial down here.
  • Two LoRAs: chain a second LoraLoader onto the first. They must share a base architecture — two SDXL ones compose, an SDXL and a Flux one don't.
  • Every workflow in the pack already has a LoraLoader in it, bypassed (purple, and it does nothing). Select it and press Ctrl-B to switch it on, then pick your LoRA. You don't have to work out where it goes or what to wire it between.
  • Match the family: the bypassed loader defaults to one of the overnight SDXL runs, so in the Flux graphs you'll need to change it to a Flux LoRA before enabling it.

5 · Getting your images back

Three ways, pick by how many you want.

One image — right-click it in the ComfyUI browser → Save Image.

A few, chosen by eye — browse the output folder like a directory and click what you want: http://desktop-sp62bqg.taild599ce.ts.net:8772. Newest first, nothing to install. (That's tools/serve_outputs.py, running on the box. Read-only.)

All of them, repeatedly — from your own laptop:

python tools/pull_outputs.py --since 3h
python tools/pull_outputs.py --list          # show me first
python tools/pull_outputs.py --out D:\mine   # somewhere specific

Talks to the same HTTP API the browser does, so it needs nothing installed but Python and Tailscale. Already-downloaded files are skipped, so run it as often as you like. The PNGs keep their embedded workflow, so anything you pull down still rebuilds its graph.

6 · When a workflow wants a node you haven't got

Red boxes on the canvas means missing custom nodes.

Manager → Install Missing Custom Nodes. It reads the graph, works out which packs it needs, fetches them.

⚠️ Custom nodes load at startup, so installing one means a restart — which on the shared box drops everyone's session. Don't install anything on 8188 during the workshop. On your own machine, restart freely. If you need to experiment during a session, run a second ComfyUI on --port 8189.

7 · Your own install, afterwards

The box goes away; this doesn't.

  1. Desktop installer from https://comfy.org if you want it to just work, or git clone https://github.com/comfyanonymous/ComfyUI if you want to see the parts.
  2. Install ComfyUI-Manager — https://github.com/ltdrdata/ComfyUI-Manager. Do this before anything else; it's how you install everything else safely.
  3. Point it at models you already have rather than downloading 20 GB again. Copy comfyui/extra_model_paths.yaml from this repo and edit the paths.

The models-on-another-drive trick

Worth knowing even if you never leave one machine. ComfyUI reads extra_model_paths.yaml at startup and adds those folders to whatever is in <ComfyUI>/models/, so nothing that already worked stops working.

my_models:
    base_path: D:\model backups
    checkpoints: checkpoints
    loras: loras
    vae: vae

Two things that will bite you:

  • Leave Windows paths unquoted. In YAML a double-quoted scalar treats \ as an escape, so "D:\model backups" silently becomes something else entirely.
  • ComfyUI searches these folders recursively. Point checkpoints: at a big mixed archive and you get every CLIP weight and sub-VAE in the checkpoint dropdown — on the box that was 84 entries of which 19 were loadable. Either keep a clean folder, or use tools/link_checkpoints.ps1, which hardlinks just the real checkpoints into one place (no disk cost, originals untouched).

Restart ComfyUI after editing the file. New model files are picked up without a restart; changes to this file are not.

8 · Where to get more

  • Official examples — https://comfyanonymous.github.io/ComfyUI_examples/ — every workflow as a drag-in PNG. The best library there is.
  • r/comfyui — where workflows actually circulate.
  • Custom-node docs — https://docs.comfy.org — paste these at an LLM with a plain-English description and it will scaffold a working node. A custom node is a small Python class: declare inputs, declare outputs, write the function.
