LoRA Workshop

Two days  ·  Photos in, trained LoRA out

Take twenty photographs of one subject, and by tomorrow morning have a model that knows it well enough to put it anywhere.

Everything runs on a shared GPU box. Your laptop is a thin client — there is nothing to install beyond a browser, an SSH client and Tailscale, and no GPU required at your end. Two web pages do the captioning and the watching; two commands submit a run and follow it.

The queue runs overnight, so the ambitious job is the one you leave behind when you go home. This page is the whole workshop: what to do before you arrive, what to do on the day, and what to do when it misbehaves.

Use the name, never an IP

The box has a different 100.x address for every person it is shared with — George's address for it is not yours. The full name resolves to whichever one is right for you. An IP copied off someone else's screen will simply time out.

Both pages need nothing but a browser and an accepted Tailscale share. If a page won't load, start the services — safe to run at any time, and it will not restart the queue worker while a job is training:

ssh gpubox "powershell -File D:\workshop\start.ps1"

Before you arrive

Four things, none of them need a GPU

Do this a few days before, not the night before — if your SSH key isn't on the box yet, George has to add it, and that isn't instant.

1 · Tailscale — how you reach the box

Install from tailscale.com and sign in. George will share the box with you by link; accept the share before running the checks below.

The first-run wizard tries to walk you through building your own network and can trap you in a loop. Take the "I already know how to use Tailscale" escape to reach the normal client, then open the share link.

Once accepted, the box appears in tailscale status on the line ending in George's email. Two things worth knowing, because they cause most of the confusion:

  • the box's short name does not resolve for you at all — only the full …ts.net name does;
  • Tailscale gives the box a different address for every person it's shared with, so IPs are not transferable between people.
tailscale status

The box is the line with George's email on it; its address is the first column.

2 · SSH — and the one shortcut worth setting up

An SSH client is already built into Windows 10+, macOS and Linux. Send George your public key — ~/.ssh/id_ed25519.pub, or make one with ssh-keygen -t ed25519 — so he can add it to the box.

Your username on the box is not your laptop username, and it contains spaces and brackets, which makes it awkward to type. Put this in ~/.ssh/config (no file extension; on Windows it's C:\Users\<you>\.ssh\config):

Host gpubox
    HostName desktop-sp62bqg.taild599ce.ts.net
    User <the username George gives you>

Now ssh gpubox just works, and so does scp … gpubox:.

Skipping the config file

If you'd rather type it each time, this works — but only on OpenSSH 9.5 and older, which is what Windows 11 currently ships:

ssh "george (stable diff)@desktop-sp62bqg.taild599ce.ts.net"

OpenSSH 9.6 added a check that rejects brackets in a command-line username, so on current macOS, on Linux, and in Git Bash the same line fails with remote username contains invalid characters. Check with ssh -V. This form works on every version, in both PowerShell and bash:

ssh -o "User='george (stable diff)'" desktop-sp62bqg.taild599ce.ts.net

The quoting is load-bearing: the inner single quotes are what let the config parser take the name as one value.

The box is a Windows machine

Your laptop can be anything, but when you ssh in you land in cmd — type powershell first, every time. You don't need to learn PowerShell; every command you'll actually run is written out ready to paste.

3 · Git and Python on your laptop

Python 3.10+ for the queue client and light scripts. Neither needs a GPU.

winget install Git.Git                 # Windows
winget install Python.Python.3.12      # tick "Add to PATH"

brew install git python@3.12           # macOS
sudo apt install git python3 python3-pip python3-venv   # Linux

Then, after cloning the repo:

python -m pip install -r requirements.txt

On macOS and Linux use python3 if python isn't found.

4 · Run the sanity check

This checks Python, git, ssh, your key, Tailscale, that the box answers, that your login works, and the dashboard. It changes nothing on the box.

python tools/check_setup.py --ssh-alias gpubox

The box's address is already the default, so there's nothing to fill in. [--] lines are warnings worth reading; [XX] lines come with instructions for fixing them.

Also before Day 1 — your dataset

Complete the intent section of the run card, upload your images, and arrange for automatic captioning on the box. The live session is for auditing captions and submitting, not for waiting on three full datasets to caption.

What makes a good set: 20–40 images, one subject, at least 1024 px on the short edge. Variety in pose, lighting and background; the thing you want the model to learn should be the only constant.

On the day

Caption · configure · submit · collect

1 · Caption your images

On the captioning page. Your name is your folder — it's what finds your images and your previous configs. Your trigger word is a rare token prefixed to every caption.

  1. Drop your images on the page.
  2. Remove the ones you don't want before captioning.
  3. Pick a style, or type a custom instruction, and press Caption — about 15 s per image.
  4. Read every caption and fix it. This is the actual work.
  5. Save captions. The timestamp is the confirmation — if it doesn't move, it didn't save.
The one idea worth carrying

Caption what you want to stay changeable. Leave out what you want baked in to the trigger word. If every photo is captioned "wearing a red coat", the coat stays changeable; if you never mention it, the trigger learns it.

Captions save as <image>.txt next to each image — that's what training reads, so there's no export step. Save before you submit: training reads the files at the moment the job starts.

2 · Make the training config

Panel 3 on the same page. Pick a base model, check the sample prompts, press Make config. It writes the .yaml on the box, already pointed at your images, and shows you the exact submit command.

You can also start from a previous config — the dropdown lists your earlier runs, and your most recent one's sample prompts load automatically. Change the model or a couple of words and press Make config for the next version. Each press makes a new version, so nothing is ever overwritten.

Sample prompts

Include one you expect to fail. The sample grid is the only instrument you get in the morning, and a grid of successes tells you nothing.

Leave Make GIFs of the samples ticked. When the run finishes, each sample prompt's images are stitched into one looping GIF, half a second a frame, from the first step to the last — they land in sample_gifs beside samples. Watching the likeness arrive and then curdle takes about seven seconds; finding the same thing by clicking through ninety JPEGs takes rather longer.

3 · Submit

ssh gpubox
powershell
$py = "C:\Users\George (Stable Diff)\Documents\Stable diff\GUI\ComfyUI\Scripts\python.exe"
cd D:\workshop\loraq
& $py loraq.py submit "D:\workshop\configs\<name>\<name>_sdxl_v1.yaml" --owner <name> --steps 3500

Before a big overnight run, check the GPU is actually free:

nvidia-smi --query-gpu=memory.free --format=csv,noheader

Under ~14 GB free means the captioner is still holding the GPU. Press Free the GPU on the captioning page, or wait fifteen minutes and it releases on its own.

The queue is fair, so use it

Runs are round-robin by owner: everyone's first run goes before anyone's second. Submit a safe one early and the ambitious one second, and you get both.

4 · Watch, then go home

The dashboard and loraq.py ls both show what each job is doing. A checkpoint and a sample grid land every 250 steps, and the queue survives you logging out.

19  geo  geo_flux2_klein_v2  running  0:11:17  3500  step 262/3500 (7%)  loss 0.521  eta 1:11:14
20  ana  ana_sdxl_v1         queued                  next up

You'll also see loading model, caching latents and sampling. A step count that stops moving while it says sampling is normal — a sample grid takes a minute. Failed jobs show the error.

5 · Collect

scp gpubox:'D:/workshop/loraq/output/<run>/*.safetensors' .
scp -r gpubox:'D:/workshop/loraq/output/<run>/samples' .
scp -r gpubox:'D:/workshop/loraq/output/<run>/sample_gifs' .

The .safetensors file is your LoRA. Drop it in models/loras/ in ComfyUI or A1111 and it's ready to use.

Starting and restarting

FlagEffect
start.ps1start whatever isn't running, wait until both pages answer
-Statusreport only, start nothing
-Restartstop and restart everything, after editing a tool

It refuses to restart the queue worker while a job is training — that would kill the run. A manual kill won't refuse, so use the script.

When it goes wrong

In rough order of how often it happens

SymptomFix
Tailscale shows the device but the page times out You're on an IP that isn't yours. Use the full name. If it won't resolve, run tailscale status — the box is the line with George's email, and its address is the first column.
A page won't load at all Run start.ps1.
remote username contains invalid characters Your OpenSSH is 9.6+. Use the -o "User='…'" form, or the config file.
'Get-CimInstance' is not recognized You're in cmd. Type powershell.
Job fails in ~30 s, FileNotFoundError The config points somewhere that doesn't exist. Regenerate it from the page.
Job fails, CUDA out of memory The captioner still holds the GPU. Press Free the GPU.
"loading joycaption…" never finishes Started by hand instead of via start.ps1. Re-run it with -Restart.
The previous-configs dropdown is empty It's found by the Your name box at the top of the page. No name, no list.
Samples look blurry Images under 1024 px were upscaled.
"nothing to do" when captioning Everything already has a caption. Tick redo existing.
Trained on raw captions You submitted before pressing Save.
