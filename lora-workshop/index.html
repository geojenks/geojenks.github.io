LoRA Workshop

Two days. Photographs of one subject go in, and a trained LoRA comes out: a small file you can drop into ComfyUI to put that subject anywhere.

All of it runs on a remote desktop with a big GPU in it. Your laptop is only a browser and an SSH client, so there is nothing to install and no GPU needed at your end. Here is what sits where.

Day 1 was how the models work, captioning, and getting everyone's first runs into the queue overnight. Day 2 is ComfyUI and what to do with the files that came out. The guide below is the whole process, from installing Tailscale to collecting the trained file.

Install preliminaries

Two of these you need, two are optional. It is a fair bit to ask and nobody has to have finished it alone, so if any of it is still outstanding we can do it together. What each one is for:

Tailscale, required

The desktop is not on the public internet. Tailscale is a private network that puts your laptop and the desktop on the same one, which is how the browser reaches the two pages and how ssh gets in. Without it nothing else on this page works.

Install from tailscale.com and sign in. I share the machine with you by link; accept the share before trying anything else.

The first-run wizard tries to walk you through building your own network and can trap you in a loop. Take the "I already know how to use Tailscale" escape to get to the normal client, then open the share link.

Once accepted, the machine appears in tailscale status on the line with my email on it, and its address is the first column. Two things cause most of the confusion: the short name does not resolve for you at all, only the full .ts.net one does; and the address is different for every person it is shared with, so addresses are not transferable.

tailscale status
[insert picture of the Tailscale machine list, with the shared device and its address pointed out]
SSH, required

You need a shell on the desktop to submit a training run and to copy the finished file back. A client is already built into Windows 10 and later, macOS and Linux, so there is nothing to install. Send me your public key (~/.ssh/id_ed25519.pub, or make one with ssh-keygen -t ed25519) and I will add it.

Your username on the desktop is not your laptop username, and it contains spaces and brackets, which makes it awkward to type. Put this in ~/.ssh/config (no file extension; on Windows that is C:\Users\<you>\.ssh\config):

Host gpubox
    HostName desktop-sp62bqg.taild599ce.ts.net
    User <the username I give you>

After that ssh gpubox works, and so does scp … gpubox:.

Typing it out instead

If you would rather not keep a config file, this works, but only on OpenSSH 9.5 and older, which is what Windows 11 currently ships:

ssh "george (stable diff)@desktop-sp62bqg.taild599ce.ts.net"

OpenSSH 9.6 added a check that rejects brackets in a username given on the command line, so on current macOS, on Linux and in Git Bash that same line fails with remote username contains invalid characters. Check yours with ssh -V. This form works on every version, in both PowerShell and bash, and the inner single quotes are what make it work:

ssh -o "User='george (stable diff)'" desktop-sp62bqg.taild599ce.ts.net

The desktop is a Windows machine. Your laptop can be anything, but when you ssh in you land in cmd, so type powershell first, every time. You do not need to learn PowerShell; every command you will actually run is written out below ready to paste.

Python, optional

Nothing you do needs Python on your laptop. Training, captioning and the queue all run on the remote desktop, using its Python, and the two pages are just web pages. The only reason to install it is to run the setup checker below, which is a single file and uses nothing beyond the standard library.

Only useful if you want the kit on your own machine, to read the configs and docs offline or to keep up with changes. GitHub will also hand you a zip of the repository, which is just as good for reading. Nothing in the workshop asks you to commit anything.

The setup checker, optional

One script that tells you which of the above is in place: ssh, your key, Tailscale, whether the desktop answers, whether your login works, and whether the two pages are up. It changes nothing on the desktop, and it is worth running once before a session so that any fixing happens before we are all sitting down. It needs Python and the repository.

python tools/check_setup.py --ssh-alias gpubox

The address is already the default, so there is nothing to fill in. [--] lines are warnings worth reading; [XX] lines come with instructions for fixing them.

Your dataset

Twenty to forty images of one subject, at least 1024 px on the short edge. Variety in pose, lighting and background: the thing you want the model to learn should be the only constant. Captioning a full set takes a while, so it is worth uploading and captioning before a session rather than during one.

Caption, configure, submit, collect

1. Caption your images

On the captioning page. Your name is your folder, and it is what finds your images and your previous configs. Your trigger word is a rare token put at the front of every caption, and it is what you will type later to summon the subject.

  1. Drop your images on the page.
  2. Remove the ones you do not want, before captioning.
  3. Pick a captioning style, or type a custom instruction, and press Caption. It takes about 15 seconds an image.
  4. Read every caption and fix or edit as needed. This can be a bit boring.
  5. Press Save captions. The timestamp is the confirmation: if it does not move, it did not save.
[insert picture of the captioning page with a set part-captioned]

Caption what you want to stay changeable, and leave out what you want baked into the trigger word. If every photo is captioned "wearing a red coat", the coat stays changeable. If you never mention it, the trigger word learns it.

Captions save as <image>.txt next to each image, which is what training reads, so there is no export step. Save before you submit, because training reads the files at the moment the job starts.

2. Make the training config

Panel 3 on the same page. Pick a base model, check the sample prompts, press Make config. It writes a .yaml file on the desktop, already pointed at your images, and shows you the exact command to submit it.

A .yaml file is a plain text settings file: names and values, one per line, indented into groups. This one says which base model to start from, where your images are, how long to train, how often to save, and which prompts to render as it goes. You never have to write one by hand, but it is readable if you want to see what you asked for.

You can also start from a previous config. The dropdown lists your earlier runs, and your most recent one's sample prompts load automatically. Change the model or a couple of words and press Make config again for the next version. Each press makes a new version, so nothing is overwritten.

Include one sample prompt you expect to fail. The sample images are the only instrument you get in the morning, and a set of successes tells you nothing about where the edge is.

Leave "Make GIFs of the samples" ticked. When the run finishes, each sample prompt's images are stitched into one looping GIF, half a second a frame, with the step count in the corner. They land in sample_gifs next to samples. Watching the likeness arrive and then curdle takes about seven seconds; finding the same thing by clicking through ninety JPEGs takes rather longer.

3. Submit

ssh gpubox
powershell
$py = "C:\Users\George (Stable Diff)\Documents\Stable diff\GUI\ComfyUI\Scripts\python.exe"
cd D:\workshop\loraq
& $py loraq.py submit "D:\workshop\configs\<name>\<name>_sdxl_v1.yaml" --owner <name> --steps 3500

All of us can submit as many runs as we like. They queue up and run one at a time, and the queue is visible on the dashboard.

Before a long overnight run, check the GPU is actually free:

nvidia-smi --query-gpu=memory.free --format=csv,noheader

Under about 14 GB free means the captioning model is still loaded. Press "Free the GPU" on the captioning page, or wait fifteen minutes and it releases on its own.

4. Watch, then do something else while it trains

The dashboard is the nicer way to follow a run. It shows every job, what it is currently doing, and the most recent sample images, and it refreshes itself, so it is the thing to leave open on a second screen. You can pause and resume the whole queue from it, which is how you get the GPU back for ComfyUI without losing a run, and you can cancel a job or move one up and down the order.

A checkpoint and a set of samples land every 250 steps, and the queue keeps running after you close the laptop. From a shell, loraq.py ls is the same information as text:

19  geo  geo_flux2_klein_v2  running  0:11:17  3500  step 262/3500 (7%)  loss 0.521  eta 1:11:14
20  ana  ana_sdxl_v1         queued                  next up

You will also see loading model, caching latents and sampling. A step count that stops moving while it says sampling is normal, because rendering the samples takes a minute or so. Failed jobs show their error.

5. Collect

scp gpubox:'D:/workshop/loraq/output/<run>/*.safetensors' .
scp -r gpubox:'D:/workshop/loraq/output/<run>/samples' .
scp -r gpubox:'D:/workshop/loraq/output/<run>/sample_gifs' .

The .safetensors file is your LoRA. Put it in models/loras/ in ComfyUI or A1111 and it is ready to use. There is one per checkpoint, so take the step number the samples say is best rather than the last one by default.

CommandWhat it does

Starting and restarting the services

FlagEffect
start.ps1start whatever is not running, wait until both pages answer
-Statusreport only, start nothing
-Restartstop and restart everything, after editing a tool

If a job is training, -Restart leaves the queue alone and only restarts the two pages, so you can run it mid-run without killing anyone's job.
